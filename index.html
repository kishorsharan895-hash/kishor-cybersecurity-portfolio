ANALYST WORKFLOW / CASE STUDY

How I investigate an alert.

A practical SOC L1-style walkthrough showing evidence collection, context checks, process analysis and a documented conclusion.

⌁

Alert triage

Record alert source, severity, timestamp, host and user. Confirm what triggered the alert and prioritise by potential impact.

⌕

Collect evidence

Review relevant Windows Event Logs or Sysmon events, process name, parent process, file path and available reputation context.

⌘

Correlate & analyse

Compare event timing and user activity. Check whether the process or login pattern fits normal behaviour and look for supporting indicators.

✓

Document finding

Summarise evidence, state what remains unknown, recommend next action and record a reasoned classification for review.

SAMPLE CASE / NOT A REAL INCIDENT

Example: repeated login failures

Training scenario for demonstrating an investigation process.

Evidence: Multiple failed sign-in events close together on one account.

Analysis: Check source address, successful logins after failures, known user activity and other related events before deciding.

Conclusion: Needs further validation. Repeated failures alone are not proof of compromise; escalate if corroborating evidence supports suspicious activity.
